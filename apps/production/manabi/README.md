# マナビー（本番版・旧称まなび）

テーマを1行書くとAI（Claude）が4択の問題セット（10/20/30問）を作り、URL（`/<10文字ID>`）で共有すると全員が同じ問題を解ける学びのドリル。 https://manabi.insightlens.jp/

`apps/ai-tools` の `/manabi`（旧 osarai）を独立させたもの（2026-10-13）。**ログイン・課金は持たない**（共有リンクをLINEで受けた人がそのまま解けることが価値のため。kikigaki 本番版との違い）。
旧 `https://<ai-tools>/manabi/**`・`/osarai/**` は ai-tools の routeRules で新ドメインの同じパスへ301する。

## 画面

| ルート | 内容 |
|---|---|
| `/` | テーマ・問題数・「みんなの問題に載せる」を決めて作る。最近の問題（端末内） |
| `/<id>` | 問題を解く。途中再開・結果で全問見返し・深掘りテーマの提案 |
| `/explore` | みんなの問題（公開にされたセットだけ。問題の中身は返さない） |
| `/print/<id>` | A4問題集（`window.print()` →「PDFに保存」） |

`/explore` と `/print` は静的ルートなので動的ルート `/[id]` より先に解決される（IDは英数10文字なので衝突しない）。

## 作りの前提

- **同じ問題集は1回しか解けない**（2026-10-19〜）。判定は端末の localStorage の解答控え（`manabi-run-v1:<id>`）だけで、別端末・ブラウザのデータ消去では解き直せてしまう（ログインが無いため）。解き終えた問題を開くと結果画面に直行し、解き直し・もう一度のボタンは無い。
- 作成者の名前（任意・20字）は、作るときに入れた文字を問題に付けて、問題名の右に出すだけ（トップの履歴・みんなの問題・開始画面）。前回の名前は端末の localStorage（`manabi-name-v1`）に覚えて次回から入力済みにする。**誰のものかの管理（ログイン・本人確認）は持たない**ので、題名の後からの変更・名前での絞り込み・名前の重複防止はできない（やるならユーザー管理が要る）。列は `manabi_sets.creator_name`（`ensureManabiTables()` が無ければ足す）。
- トップ右上の「正解 N問」は、端末内の問題集ごとの正解数（`manabi-correct-v1`）の合計。
- 解答・点数はサーバーに送らない。端末の localStorage に途中経過・直近結果だけ（ドメインが変わったので旧ドメインの履歴は引き継がれない）。
- **他の端末とつなぐ（同期コード、`/sync`）**: ログインの代わりに、推測できない12文字のコードを合鍵にして、名前・問題集ごとの正解数・回答した問題の一覧（計5〜15KB）だけを D1 の `manabi_sync` に預ける。つないだあとは、トップを開いたときと解いた後（2秒まとめ）に自動で同期する。統合はサーバー側（正解数は大きいほう、一覧はIDの和集合）なので2台が同時でも消えない。**解答の途中経過（`manabi-run-v1:*`）は運ばない**ので、別端末で同じ問題を開くと最初から解ける＝「1回しか解けない」は端末ごとのまま。コードを知っている人は誰でも読み書きできる（IPあたり発行は1日10回まで）。テーブルは `ensureSyncTable()` が無ければ作る（`003_sync.sql` と同じ内容）。QRは未対応（コードかリンクをコピーして渡す）。
- **対象（大人向け／子供向け）**: トップの問題数の上のタブで選ぶ。既定は大人向け（従来どおりテーマから水準を読み取る）。子供向けは小学5〜6年生ぐらいの言葉・水準で、習った漢字は使い、難しい漢字は（）で読みがなを付け、考えさせる問題を中心にする（`manabi-ai.ts` の「対象の指定」「対象が子供向けのとき」）。対象は問題セットには保存しない（水準は AI がつける `level` に出る）。対象・問題数・公開の選択は端末の localStorage（`manabi-options-v1`）に覚えて次回から選択済みにする。
- **問題ごとのイイね**（2026-10-20〜）: 解答後の解説の下に♡ボタンと件数。結果画面の見返しにも件数（0件は出さない）とボタン。1人1回・取り消し無し。「1人」は端末の localStorage（`manabi-voter-v1`）のランダムIDで、`manabi_likes (set_id, q_index, voter)` の主キーで重複を弾く＝ログインが無いので、別端末・データ消去・IDの偽装で複数回押せてしまう。API は `GET/POST /api/sets/<id>/likes`。テーブルは `ensureLikesTable()` が無ければ作る（`004_likes.sql` と同じ内容）。
- **クリア人数**（2026-10-21〜）: 問題集を最後の問題まで解き終えた（結果画面に着いた）人数。点数は問わない。イイねと同じ端末ランダムIDで `manabi_clears (set_id, voter)` の主キーにより同じ端末は1回だけ数える（別端末・データ消去・ID偽造では増やせてしまう）。解き終えたときに `POST /api/sets/<id>/clear`。表示は「みんなの問題」の一覧と問題を開いた最初の画面（`GET /api/sets/<id>` の `clearCount`）。トップの端末内履歴には出さない。テーブルは `ensureClearsTable()` が無ければ作る（`005_clears.sql` と同じ内容）。この機能を入れる前に解き終えた分は数えていない。
- 点数は100点満点（内部は正答率の整数%をそのまま使い、表示だけ「点」）。トップの履歴の見出しは「回答した問題」。
- **AI代の歯止めは IP（ハッシュ）ごとに1日10セット（2026-10-19に30から変更）**（`MANABI_DAILY_LIMIT`）とテーマ200字上限だけ。ログインが無いので他に歯止めは無い。公開サービスとして使われ方が変わったらここを見直す。
- 生成は2段（論点を決める→5問ずつ並列で作問）。選択肢の長さで正解が当たらないよう `correct_len` とサーバーの `pickDistractors()` で緩和している（`server/utils/manabi-ai.ts`）。作問プロンプトを触ったら正解が最長の問題の割合を測り直すこと。
- テーブルは `manabi_sets`（ai-tools 時代の `osarai_sets` から名前だけ変えた）。`ensureManabiTables()` が最初のアクセスで作る保険を持つ。D1 が無い環境（素の dev）ではプロセス内 Map に置く。

## ローカルで動かす

```bash
cp .env.example .env          # NUXT_ANTHROPIC_API_KEY を入れる
yarn dev:manabi               # :3010
yarn workspace manabi typecheck
```

**`yarn dev` 中に `yarn build` を実行しないこと**（`.nuxt` を共有しているため壊れる）。

## セットアップ（本番）

```bash
wrangler d1 create manabi-db           # 済み。database_id は wrangler.toml に書いてある
wrangler d1 execute manabi-db --remote --file src/server/db/001_init.sql
wrangler secret put NUXT_ANTHROPIC_API_KEY
```

デプロイは `.github/workflows/deploy-manabi.yml`（`apps/production/manabi/**` への push で Workers へ）。
